# 예약 취소 후 상품 목록·상세 상태 동기화 검증

검증일: 2026-11-08. 실제 DB가 아닌 Chromium과 모의 API를 사용한 재현·회귀 검증이다.

## 수정 전 실패 근거

서비스 코드는 `bf3100ce1223c00f8a4e712e0cfca3fe6548ee0e` 그대로 두고 `scripts/reservation-browser-regression.mjs`에 재현 조건만 추가했다. 당시 `git diff --name-only`에는 이 테스트 스크립트만 표시됐다.

- 최초 `/api/session/state`와 상품 목록 응답: 상품 `reserved`, 현재 구매자의 예약 `active`.
- 취소 `PATCH` 성공 후 모의 서버 응답: 예약 `cancelled`, 상품 `active`.
- React 렌더링과 연속 두 번의 `requestAnimationFrame`을 기다린 뒤 목록 카드와 열린 상세를 검사했다.
- `pnpm run build`: 종료 코드 0.
- 로컬 빌드에서 `pnpm run test:reservation:browser`: **종료 코드 1**.

실제로 실패한 단언은 다음과 같다. API 거절이나 테스트 도구 오류가 아니라 서버 상태와 화면 상태의 불일치로 실패했다.

```text
취소 후 렌더링·상세 동기화가 끝나도 서버 상태와 불일치
actual:   { cardReserved: true,  detailReserved: true }
expected: { cardReserved: false, detailReserved: false }
```

## 최소 수정 내용

1. 예약 결과만 보고 `selectedProduct.status`를 무조건 `Available`로 지정하던 코드를 제거했다.
2. 기존 `refreshMarketplaceReservations`에서 취소 응답 확인 후 서버 상태를 조회하고, 기존 `remotePublicProducts`와 서버 상품에 해당하는 `userProducts`, 예약 기록을 함께 갱신한다. 로컬 체험 상품과 기존 소유권 표시는 보존한다.
3. 목록 원천이 변경되면 기존 상세 동기화 경로가 열린 상세에도 같은 상품을 반영한다. 상품이 공개 목록과 내 상품 모두에서 사라졌으면 해당 상세를 닫고 `listing` 주소값을 정리한다.
4. 다른 예약으로 서버 상태가 `reserved`라면 그대로 표시하고 내 활성 예약이 없을 때 취소 버튼을 활성화하지 않는다. 서버의 `sold`는 목록·상세 모두 판매 완료로 표시한다. 숨김으로 공개 목록에서 빠진 상품은 노출하지 않는다.
5. 취소 거절 시 상태를 바꾸지 않는다. 취소는 성공했어도 상품 재조회가 실패하면 성공 안내를 표시하지 않고, 마지막 확인 상태와 서버 확인 버튼을 유지한다.
6. `PickupSchedule`은 기존 export 타입을 import해 중복 정의를 없앴다. 테스트의 사용하지 않는 문구 8개만 제거했으며 유효한 단언은 삭제하지 않았다.

새 상태 관리 라이브러리·스키마·공통 추상화는 추가하지 않았다. 인증 설정·운영 환경변수·DB 스키마·Ponytail 설치 원본과 실행 훅은 변경하지 않았다.

## 회귀 검증 범위

기존 예약 모의 브라우저 20개 사례에 다음 여섯 조건을 한국어·영어로 추가했다.

- 최초 `reserved` 상품의 정상 취소.
- 취소 거절: 서버 상품 `reserved`, 예약 `active` 유지.
- 내 예약 취소 후 다른 예약 때문에 상품 `reserved` 유지.
- 취소 후 서버 상품 `sold` 유지.
- 취소 후 상품이 숨겨져 공개 목록에서 제외됨.
- 취소 성공 후 상품 재조회 실패, 확인 버튼으로 조회 재시도.

상태가 계속 공개되는 경우 목록 카드·열린 상세·닫았다 다시 연 상세·서버 응답을 반영한 새로고침에서 상태 색상과 문구를 함께 비교한다. 숨김 상품은 목록·상세 미노출과 주소 정리를 검사한다. API 요청은 전부 모의 응답으로 처리하며, 등록하지 않은 API와 외부 통신도 실제 서버로 보내지 않는다.

실행 명령과 최종 통과 결과는 [README 검증 기록](../README.md#검증-기록)에 기록한다. 이전 테스트 수와 날짜는 이번 결과로 대체하지 않는다.

## Ponytail 재리뷰

설치된 `ponytail-review` 지침을 명시적으로 적용해 변경분, 상품 변환·예약 어댑터, 취소 API, 기존 목록·상세 동기화, 테스트와 문서를 대조했다. 여러 구매자의 상태가 동시에 달라질 수 있는 서비스로 가정했다.

검토 범위에서 상품 상태를 예약 상태만으로 추정하는 분기를 제거했고, 실패·재조회·중복 요청 보호와 샘플 제한을 유지했다. 서버가 반환한 판매 완료·다른 예약·숨김 상태를 모의 UI 검증으로 확인했다. 줄 수를 맞추기 위한 삭제나 전체 저장소 감사는 하지 않았다.

실제 DB의 취소 처리·경쟁 상태·복구, 인증 계정 연결, Firefox·WebKit·실기기는 이번에 검증하지 않았다. 서버 취소 API나 DB 트랜잭션을 바꾼 작업도 아니다. 모의 응답 통과를 실제 Supabase 통합 통과로 보고하지 않는다.
