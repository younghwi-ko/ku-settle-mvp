# 미사용 관리자 구현 삭제 기록

## 범위와 삭제 근거 — 2026-11-09

기준 커밋은 `ba12311`이다. `ponytail full`을 적용해 `app/page.tsx`의 두 미사용 구현만 확인하고 삭제했다.

- 저장소 전체 소스·테스트·스크립트·문서를 검색했을 때 `LegacyAdminServerPanel`과 `AdminPanel`은 해당 파일의 선언부에만 있었다. 두 함수는 export되지 않았으며 JSX 렌더링·콜백·동적 참조가 없었다.
- 실제 진입은 데모 모드의 프로필 메뉴 → 관리자 패널 → `go("admin")` → 현재 `AdminServerPanel` 렌더링이다. `app/components/admin-server-panel.tsx`와 인증 API·서버 권한 검사는 변경하지 않았다.
- 기준 파일의 1014–1046행을 삭제했다. 두 함수, 전용 `AdminOverviewData`, 해당 영역의 `no-unused-vars` 억제·해제 주석을 포함한다. 함수 내부 전용 상태·처리 함수도 함께 제거됐다.
- 사용하던 import와 공유 타입·함수는 남은 화면에서도 참조되므로 보존했다. 번역 리소스·CSS·다른 미사용 후보는 이번 범위에서 삭제하지 않았다.
- 기준 파일에서 이 연속 범위만 제외한 결과가 수정 파일과 같은지 비교했다. 현재 관리자 컴포넌트가 기준 커밋과 같은지도 확인했다. 비교 시 줄바꿈은 LF로 정규화했다.

관리자 진입 브라우저 검증은 새 컨텍스트에서 일반 게스트의 메뉴 숨김을 확인하고, 기존 UI로 브라우저 로컬 데이터만 초기화해 데모 모드에 진입한다. 프로필의 관리자 메뉴를 눌러 운영자 이름·토큰 입력과 비활성 로그인 버튼을 확인한다. 관리자 인증 요청은 보내지 않고 인증 데이터 화면이 열리지 않는지도 확인한다.

최초 추가 테스트는 게스트 상태에서 데모 전용 관리자 메뉴를 찾도록 잘못 구성해 타임아웃이 발생했다. 서비스 코드는 변경하지 않고 기존 진입 조건을 따르도록 테스트를 수정한 뒤 위 6/6 결과를 확인했다.

## Ponytail 재리뷰

`ponytail-review`로 삭제 diff, 실제 호출부·메뉴의 모드 조건, 보존한 관리자 컴포넌트의 인증·조회·수정 경로와 관련 테스트를 대조했다. 여러 사용자가 같은 서비스에 접근하는 환경을 전제로 검토했지만, 삭제된 함수는 실행 경로가 없어 서버 동시성 처리에는 영향을 주지 않는다.

확인된 기능 손실이나 추가 수정이 필요한 문제는 없었다. 공유 함수·타입·import·번역 리소스를 더 삭제할 근거도 없어 유지했다. 판정은 이번 미사용 구현 삭제 범위에서 반영 가능이다.

## 한계와 보존한 항목

실제 관리자 토큰 인증, 로그인 후 서버 데이터 조회·수정, DB 저장·동시성은 이번에 검증하지 않았다. 브라우저 검증은 운영 API·외부·쓰기 요청을 차단하고 새 브라우저 컨텍스트만 사용한다. Firefox·WebKit·실기기는 미검증이다.

인증 설정·운영 환경변수·DB 스키마·실제 사용자 데이터는 변경하지 않았다. 기존 미커밋 `.agents/skills/ponytail/`과 `docs/ponytail-development-usage.md`도 이번 정리 커밋에 포함하지 않는다.
